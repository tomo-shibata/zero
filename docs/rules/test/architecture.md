# テストルール

テスト（`**/test/**`, `e2e/**`, `*_test.go` など）を読む・書く・レビューするときに、先に読むこと。
関連: [バックエンドルール](../backend/architecture.md)、[フロントエンドルール](../frontend/architecture.md)。

## 1. テストは実装から独立させる

- テストコードは **実装とは別に作る**（実装に引きずられて書かない）。
- テストの独立性を保つこと。

## 2. 仕様からテストを作る（コードからは作らない）

- テストは **仕様書から** 作成する。
- **実装コードからテストを作らない**。
- **理由**: コードから起こすと、実装をそのままなぞる **トートロジーテスト**（実装＝期待値になり、何も検証していないテスト）になってしまうため。

## 3. mock を使ったトートロジーテストはなるべく避ける

- mock を多用して「呼び出したことを確認するだけ」のような、実質的に何も検証しないテストは避ける。
- mock は必要最小限にとどめ、振る舞い（入力に対する出力・結果）を検証する。

## 4. テスト実行のたびにデータベースを作成する

- テスト実行のたびに**データベースを新規作成**する。
- シードファイルに **DDL / DML** が入っているので、**毎回それを実行してデータを作成**する。
- **理由**: テストが**並行（並列）で動いたときに壊れないようにするため**。テストごとにDBを独立させ、互いに干渉させない。
