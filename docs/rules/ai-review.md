# AI相互レビュールール

AIによる相互レビューの運用ルール。
関連: [ドキュメント入口](../index.md)。

## タイミングと実行方法

- **プルリクエスト作成前に必ず1回**実行する。
- レビューは、**実装を行ったセッションとは別セッションのAI**で実行する（実装者と同じ文脈でレビューしない）。

## レビューの優先度

優先度は **0 / 1 / 2** の3パターン。上から順に重い。

### 優先度0: 対応必須の修正（マージをブロックする）

- セキュリティ
- データの破壊
- 機能の誤り

→ これらは**修正しない限りマージ不可**。

### 優先度1: 推奨修正

- 深刻な潜在バグの芽
- テスト網羅の欠落

→ **合理的な理由があればスキップ可能**。スキップした上でマージしてもよい。

### 優先度2: 軽微

- コーディングスタイル
- 命名規則

→ 時間があれば修正。なければ **イシュー化してスキップ**。

## レビュー終了の条件

- **優先度0・1が一件もなければ合格**。
- **優先度2だけ**なら、修正せずマージしてよい。
- レビューが **3ラウンドを超えて循環** したら、**人間が介入して判断する**。

## 静的レビューの限界

- 差分を読む（静的な）AIレビューでは、次のような **実行時のバグは捕まらない**:
  - 表示崩れ
  - 空データ時の無限ローディング
  - 状態の取り違え
- したがって、**UI や実行時の挙動を変えたら、最後は自分で動かして確かめること**。
