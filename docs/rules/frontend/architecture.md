# フロントエンド アーキテクチャルール

`frontend/**` を読む・変更する・レビューするときに、先に読むこと。
React + TypeScript によるクリーンアーキテクチャを採用する。
関連: [開発ルール全体](../../../エージェント向けREADME.md)、[テストルール](../test/architecture.md)。

## 1. レイヤー分割と依存の向き

UI から遠い順に、関心を4層に分ける。**依存は常に内側（domain）へ向かう。**

```
app        … 画面・ルーティング・プロバイダ（最外層）
features   … 機能単位のまとまり（UI + 状態 + ユースケース）
entities   … ドメインモデルとその表示（Account, Transaction など）
shared     … 汎用UI・ユーティリティ・APIクライアント（最内層・どこからでも使える）
```

- 外側は内側に依存してよいが、**内側は外側を import してはいけない**（例: `shared` が `features` を import するのは禁止）。
- ビジネスロジック（金額計算・バリデーション等）は React に依存しない純粋な TypeScript 関数として切り出す。

## 2. ディレクトリは「機能単位（feature-based）」で切る

技術種別（components/ hooks/ …）でトップを割らず、**機能ごと**にまとめる。

```
src/
├── app/                      # エントリ・ルーティング・全体プロバイダ
├── features/
│   └── transactions/         # 例: 取引機能
│       ├── api/              #   この機能のAPI呼び出し
│       ├── components/       #   この機能専用のUI
│       ├── hooks/            #   この機能専用のロジック
│       └── index.ts          #   公開API（外からはここ経由でのみ参照）
├── entities/                 # ドメインモデル＋表示（例: account, transaction）
└── shared/
    ├── ui/                   # ボタン等の汎用コンポーネント
    ├── lib/                  # 汎用ユーティリティ
    └── api/                  # APIクライアント共通設定
```

- 機能の外からは `features/xxx/index.ts` が公開するものだけを使う（内部実装に直接触らない）。

## 3. コンポーネント設計

- **プレゼンテーション（見た目）** と **コンテナ／ロジック** を分ける。UIコンポーネントは原則として props を受け取って描画するだけにする。
- 1コンポーネント＝1つの責務（バックエンドと同じく、やることを一文で言えること）。
- ロジックはカスタムフック（`useXxx`）に閉じ込め、コンポーネントから切り離す。
- 副作用（API呼び出し等）をコンポーネント本体に直書きしない。

## 4. 状態管理

- **サーバー状態**（APIから取得するデータ）と **クライアント状態**（UIの開閉など）を混同しない。
  - サーバー状態は TanStack Query（React Query）等のデータ取得ライブラリで管理し、自前の useState でキャッシュしない。
  - クライアント状態は局所的に（必要なら Zustand 等の軽量ストア）。
- グローバルに置くのは本当に全体で必要なものだけ。まずはローカル state から始める。

## 5. 型の扱い（TypeScript）

- `strict: true` を有効にする。`any` は原則禁止（やむを得ない場合はコメントで理由を書く）。
- API のレスポンス型を定義し、境界（APIクライアント）で検証・変換してから内部に渡す（zod 等でのパースを推奨）。
- ドメインの型は `entities` に置き、UIの都合の型と混ぜない。

## 6. データ取得・API

- API 呼び出しは直接コンポーネントから行わず、`features/xxx/api` または `shared/api` 経由に集約する。
- fetch のエラー・ローディング・空状態を必ずハンドリングする。

## 7. スタイリング・命名

- コンポーネントは PascalCase、フック・関数は camelCase、ファイル名はプロジェクト内で統一する。
- マジックナンバー・文字列リテラルは定数に切り出す。

## 8. テスト

- ロジック（フック・純粋関数）を優先的にテストする。
- コンポーネントは「ユーザーが見える振る舞い」をテストする（実装詳細に依存しない。Testing Library の思想に従う）。
- 詳細は `docs/rules/test/architecture.md` に従う。
